## 1. 产品概述

### 1.1 一句话定位

**一个"创世神工作台"：让 AI 角色在一个世界里自由互动，你作为创世神随时注入变化，最终把这一切蒸馏成一本小说。**

### 1.2 产品哲学（决定 UI 的取舍）

本项目有**两层独立产物**，UI 必须清晰区分，不能混淆：

1. **素材层（模拟世界）**：角色们自由行动，产生事件流。你作为创世神拥有**全知视角**——能看见每个角色的内心独白、言语、行动、记忆沉淀。这部分是"工厂"，产出原始素材。
2. **产品层（小说）**：从事件流蒸馏出的成品小说，有起承转合、有文学性。小说正文**不强制暴露**角色的内心——那是艺术创作，由小说管线拿捏。

> **UI 核心准则**：用户在"演播室"能看穿一切；在"小说工作台"看到的是艺术成品。两者互不污染。

### 1.3 核心价值

- 让无文笔但有想法的人，通过"造世界 + 当创世神"得到一本由角色真实互动涌现出的、经得起推敲的小说。

## 2. 目标用户与场景

| 用户 | 典型场景 |
|---|---|
| 创世神（核心用户） | 建一个武侠世界 → 看着沈雁/阿蛮/柳娘自由互动 → 中途扔一只血染的信鸽 → 观察三人的反应 → 出小说 |
| 小说作者 | 用世界生成的故事素材，二次创作/导出 |
| 看客 | 只看回合流或只看小说，不介入 |

---

## 3. 核心概念（术语表，前端命名统一使用）

| 术语 | 含义 |
|---|---|
| **世界 (World)** | 一个持久化的故事容器，含世界观、地点、角色、事件流、记忆、小说 |
| **回合 (Turn)** | 一次模拟推进。所有在场角色各自"想-说-做"，产出场景正文 + 创世神视图 |
| **角色/Agent** | 有独立人格、记忆、目标的 AI 演员 |
| **内心独白 (thought)** | 角色真实想法，**仅创世神可见** |
| **言语 (speech)** | 角色说出口的话 |
| **行动 (action)** | 角色做的动作 |
| **记忆沉淀 (memories)** | 本回合角色新记下的事 |
| **导演事件 (DirectorEvent)** | 你注入的世界变化，可定向给指定角色 |
| **事件流 (Chronicle)** | 全部回合的结构化记录（内心/言语/行动/叙述/异变），小说的素材 |
| **小说 (Novel)** | 成品，含书名、叙事弧、章节 |
| **大纲 (Outline)** | 小说规划：章节划分 + 标题 + 概要 + 回合范围 |

## 5. 页面详细设计

### 5.1 世界广场 World Plaza

**目标**：入口。列出已有世界、创建新世界、进入演播室。

```
┌─────────────────────────────────────────────────────────────┐
│  World Engine 世界引擎                      [设置 ⚙]         │
│                                                              │
│  ┌─────────────┐  ┌─────────────┐  ┌─────────────┐          │
│  │ 荒山茶馆      │  │ 新建世界 [+] │  │             │          │
│  │ 回合: 12      │  │            │  │             │          │
│  │ 角色: 3      │  │            │  │             │          │
│  │ [进入]       │  │            │  │             │          │
│  └─────────────┘  └─────────────┘  └─────────────┘          │
└─────────────────────────────────────────────────────────────┘
```

**交互**：
- 加载时 `GET /api/worlds`，空列表显示"还没有世界，创建第一个吧"。
- **新建世界弹窗**：
  - 世界 ID（默认自动生成英文 id，可手改，用于持久化键）
  - 预设选择：当前仅一个预设 **《荒山茶馆》**（`presets/tavern.yaml`），选择后展示世界简介与角色
  - 提交 `POST /api/worlds` → 成功进入演播室
- 已有世界点「进入」→ `GET /api/worlds/{id}` 后进入演播室（续写）。

### 5.2 世界演播室 World Studio（核心页面）

**目标**：创世神工作台。推进回合、全知观察、注入变化。

```
┌────────────────────────────────────────────────────────────────┐
│ ← 返回   荒山茶馆    第 12 回合   [⏸ 暂停]   [▶ 推进一回合]      │
├──────────────────────────────────────────┬─────────────────────┤
│  时间线（主区，从上到下时间递增）           │  角色侧栏             │
│  ── 第 12 回合 ─────────────────────    │  ┌───────────────┐   │
│  场景正文（narrative，文学白描）           │  │ 沈雁 · 剑客     │   │
│  【创世神视图】                           │  │ 地点: 茶馆大堂   │   │
│  · 沈雁                                   │  │ 性格: 沉稳寡言   │   │
│      内心: ……                            │  └───────────────┘   │
│      说: "……"                            │  ┌───────────────┐   │
│      行动: ……                            │  │ 阿蛮 · 少年侠客 │   │
│      记忆沉淀: ……                        │  └───────────────┘   │
│  · 阿蛮                                   │  ┌───────────────┐   │
│  · 柳娘                                   │  │ 柳娘 · 老板娘  │   │
│                                          │  └───────────────┘   │
│  ── 第 11 回合 ─────────────────────    │  [⏳ 事件流] [📖 出小说]│
│  ……（更早回合折叠，可展开）               │                      │
├──────────────────────────────────────────┴─────────────────────┤
│  导演面板: [事件描述输入框........................]  @目标角色:    │
│  [☑ 沈雁][☐ 阿蛮][☐ 柳娘]      [🔥 注入世界]                    │
└────────────────────────────────────────────────────────────────┘
```

**核心交互**：

1. **推进一回合**：`POST /api/worlds/{id}/step`（body 为空）。
   - 该请求**同步阻塞数秒**（N 个角色 LLM + 叙述者），期间顶部按钮转 loading，禁止重复点击。
   - 响应后，新的回合卡片**插入时间线顶部**（最新的在最上），自动滚动到该卡片。
   - 时间线每回合卡片 = 场景正文 + 创世神视图（每个角色的 内心/说/行动/记忆沉淀）。
   - 内心独白用视觉区分（如斜体/不同底色/🔒 图标），强化"仅创世神可见"的语义。

2. **注入导演事件**：
   - 导演面板输入事件描述 + 勾选目标角色（不勾 = 全角色感知）。
   - `POST /api/worlds/{id}/step`，body = `{"event": {"content": "...", "targets": ["沈雁"]}}`。
   - 该回合卡片顶部显示 **【世界异变】** 高亮横幅，注明注入内容与感知对象。
   - 目标角色的内心独白会反映其感知（如"信鸽是冲我来的"）。

3. **事件流抽屉**：`GET /api/worlds/{id}/history?limit=50`，按回合分组展示全部结构化事件（内心/说/行动/叙述/异变），带类型标签。供创世神回看。

4. **出小说**：跳转到小说工作台（见 5.3）。

5. **暂停/续写**：暂停 = 停止自动推进（如果做了自动连播），纯手动推进可不做暂停按钮。**v1 建议手动推进为主**，自动连播留作增强。

**视觉规范**：
- 场景正文（narrative）：正文排版，字距舒展，作为"故事"呈现。
- 创世神视图：等宽/卡片式，一眼是"数据/幕后"。
- 内心独白与言语必须视觉可区分。
- 整个页面保持"舞台感"：主区是舞台，侧栏是演员表，底部是神的控制台。

### 5.3 小说工作台 Novel Studio

**目标**：从事件流产出成品小说。

```
┌────────────────────────────────────────────────────────────────┐
│ ← 返回   《荒山茶馆》  叙事弧: 三个过客相遇，一封信鸽引出旧案        │
├──────────────────────────────┬─────────────────────────────────┤
│  大纲（左侧）                  │  章节正文（右侧）                 │
│  ┌────────────────────────┐  │  ┌────────────────────────────┐ │
│  │ 1. 茶香初会  回合1-2    │  │  │  ## 第1章 茶香初会           │ │
│  │ 2. 信鸽夜来  回合3-4    │  │  │                             │ │
│  │ 3. ……                  │  │  │  正文……                    │ │
│  └────────────────────────┘  │  │                             │ │
│  [🗂 生成大纲]  [✍️ 撰写全部]   │  │  [复制] [下载 Markdown]      │ │
│  [✍️ 撰写选中]                │  └────────────────────────────┘ │
└──────────────────────────────┴─────────────────────────────────┘
```

**核心交互**：

1. **生成大纲**：`POST /api/worlds/{id}/novel/plan` → 刷新左侧大纲列表（书名、叙事弧、章节、每章概要+回合范围）。
   - 请求耗时数秒，loading。
2. **撰写章节**：
   - 全部：`POST /api/worlds/{id}/novel/write`（body 空）
   - 指定章节：先选大纲中的章节，`POST /api/worlds/{id}/novel/write` body = `{"chapters": [1,3]}`
   - 响应中章节 `content` 已填充、`status = "edited"`。**耗时较长（每章 2 次 LLM），必须逐章显示进度**（"正在写第 2/3 章…"）。
3. **阅读**：点击章节 → 右侧展示正文。未被撰写/空章节显示占位"（本章尚未撰写）"。
4. **导出**：`GET /api/worlds/{id}/novel/export` → 下载 `.md` 文件（书名/弧线/目录/正文）。

**状态提示**：
- 从演播室第一次进入、且从未 plan → 提示"还没有大纲，先生成大纲"。
- 已 plan 未 write → 章节内容为空，按钮引导撰写。

## 6. 核心交互流程（时序）

### 流程 A：造世界 → 看故事 → 注入变化
```
广场 [新建世界(荒山茶馆)] → POST /api/worlds → 进入演播室
演播室 [推进一回合]×3 → POST step → 时间线出现 3 张回合卡
演播室 [注入: 一只血染的信鸽撞进茶馆] 目标:沈雁 → POST step{event}
→ 新回合卡顶部出现【世界异变】横幅，沈雁内心/言语反映其反应
演播室 [事件流] 回看全部
```

### 流程 B：出书
```
演播室 [出小说] → 小说工作台 [生成大纲] → POST novel/plan
→ 大纲出现 → [撰写全部] → POST novel/write（逐章进度）
→ 点击章节阅读 → [下载 Markdown] → GET novel/export
```

## 7. 后端 API 契约（完整）

**Base URL**：可配置，默认 `http://127.0.0.1:8000`。所有端点前缀 `/api`。

**内容类型**：`application/json`（导出为 `text/markdown; charset=utf-8`）。

**错误格式**（FastAPI 默认）：
```json
{ "detail": "错误描述" }
```
HTTP 状态码含义：`201` 创建成功 / `200` 成功 / `404` 世界或小说不存在 / `500` LLM 调用失败等。

---

### 7.1 `GET /api/worlds`

列出所有已存在的世界 id。

**响应** `200`
```json
["w1", "w2"]
```

### 7.2 `POST /api/worlds` — 创建/加载世界

Body：
```json
{ "world_id": "my-world", "preset_path": "presets/tavern.yaml" }
```
- `world_id` 必填（默认 `"default"`）。**已存在的 id 会续写该世界**（此时 `preset_path` 被忽略）。
- `preset_path` 可选；不传用后端默认预设。

**响应** `201`（WorldSummary）：
```json
{
  "world_id": "my-world",
  "name": "荒山茶馆",
  "turn": 0,
  "setting": "边陲小镇外的荒山上……",
  "locations": ["茶馆大堂", "后院", "山路"],
  "characters": [
    { "name": "沈雁", "role": "江湖剑客", "location": "茶馆大堂", "persona": { "core": "沉稳寡言", ... } }
  ]
}
```

### 7.3 `GET /api/worlds/{world_id}` — 世界状态

响应同 WorldSummary。若世界不存在：**注意：当前后端会自动按默认预设创建**（行为等同 POST）。前端以此作"进入即续写/即创建"。

### 7.4 `POST /api/worlds/{world_id}/step` — 推进一回合（可含导演事件）

Body 可选：
```json
{ "event": { "content": "一只血染的信鸽撞进茶馆", "targets": ["沈雁"] } }
```
- `event.targets` 缺省为 `[]` 表示全角色感知。
- body 可完全省略 `{}`（纯推进）。

**响应** `200`（StepResponse）：
```json
{
  "turn": 1,
  "narrative": "茶馆里雾气氤氲，一个生面孔推门而入……",
  "agents": [
    {
      "name": "沈雁",
      "thought": "此人来路不明，我须留神他袖口下的那截刀柄。",
      "speech": "这位兄台，面生得很，打哪儿来？",
      "action": "端起茶碗，目光却暗暗扫向门口。",
      "memories": ["茶馆里来了个带刀的生面孔"]
    }
  ],
  "events": ["...最近8条事件内容..."]
}
```
**注意**：本端点同步阻塞，耗时数秒（每角色一次 LLM + 叙述者）。前端必须处理 loading 与防重复提交。

### 7.5 `GET /api/worlds/{world_id}/history?limit=20` — 事件流

**响应** `200`：
```json
[
  { "turn": 1, "kind": "thought",  "actor": "沈雁", "content": "……", "created_at": "2026-08-05T11:53:44Z" },
  { "turn": 1, "kind": "speech",   "actor": "沈雁", "content": "……", "created_at": "..." },
  { "turn": 1, "kind": "action",   "actor": "沈雁", "content": "……", "created_at": "..." },
  { "turn": 1, "kind": "narration","actor": null,   "content": "……", "created_at": "..." },
  { "turn": 1, "kind": "director", "actor": "导演", "content": "……", "created_at": "..." }
]
```
`kind` 枚举：`thought`(内心) / `speech`(说) / `action`(行动) / `narration`(叙述) / `director`(异变)。

### 7.6 `POST /api/worlds/{world_id}/novel/plan` — 生成大纲

无 body。**响应** `200`（NovelView）：
```json
{
  "title": "荒山茶馆",
  "arc": "三个过客相遇，一封信鸽引出一桩旧案。",
  "chapters": [
    { "number": 1, "title": "茶香初会", "summary": "三个过客各怀心事地相遇", "start_turn": 1, "end_turn": 2, "content": "", "status": "outlined" }
  ]
}
```

### 7.7 `POST /api/worlds/{world_id}/novel/write` — 撰写章节

Body 可选：
```json
{ "chapters": [1, 3] }
```
- 缺省 `chapters`（或 `{}`）写全部。
**响应** `200`（NovelView，章节含 `content`、`status = "edited"`）。
**耗时**：每章 2 次 LLM（writer + editor），多章明显较久，需要进度反馈。

### 7.8 `GET /api/worlds/{world_id}/novel` — 当前小说

**响应** `200`（NovelView）。**`404`**：该世界还没 plan 过，`detail` 提示先调用 `/novel/plan`。

### 7.9 `GET /api/worlds/{world_id}/novel/export` — 导出 Markdown

**响应** `200`，`Content-Type: text/markdown`，body 为完整 Markdown 书（书名/弧线/目录/章节正文）。

## 8. 前端数据模型（TypeScript，与后端一一对应）

```ts
interface WorldSummary {
  world_id: string; name: string; turn: number; setting: string;
  locations: string[];
  characters: CharacterView[];
}
interface CharacterView {
  name: string; role: string; location: string;
  persona: Record<string, unknown>;
}
interface AgentView {
  name: string; thought: string; speech: string; action: string;
  memories: string[];
}
interface StepResponse {
  turn: number; narrative: string;
  agents: AgentView[]; events: string[];
}
interface ChronicleEvent {
  turn: number; kind: "thought" | "speech" | "action" | "narration" | "director";
  actor: string | null; content: string; created_at: string;
}
interface ChapterView {
  number: number; title: string; summary: string;
  start_turn: number; end_turn: number; content: string; status: "outlined" | "edited";
}
interface NovelView { title: string; arc: string; chapters: ChapterView[]; }
```

## 9. 状态管理建议

- **服务端数据**：用 TanStack Query（React Query）缓存键：
  - `["worlds"]`、`["world", id]`、`["world", id, "history"]`、`["world", id, "novel"]`
  - step / plan / write 后用 `invalidateQueries` 刷新。
- **本地 UI 状态**：Zustand 存当前世界 id、路由、导演面板草稿、时间线折叠状态。
- **同步端点 + 乐观更新**：不要对 step 做乐观更新（结果不可预测），用 loading 遮罩等待真实响应。

## 10. 错误处理与边界

| 场景 | 处理 |
|---|---|
| 后端不可达 | 顶部横幅"无法连接后端"，设置里重试 |
| step / plan / write 超时或 500 | toast 报错，保留现场（loading 解除），允许重试；不丢已渲染的旧回合 |
| GET novel 404 | 引导文案 + 跳「生成大纲」按钮 |
| 创建世界同名续写 | 提示"已存在，将续写该世界" |
| 空 world 列表 | 空状态插画 + 新建引导 |
| 章节未撰写 | 占位"（本章尚未撰写）" |

## 11. 前端技术栈建议

| 项 | 建议 | 理由 |
|---|---|---|
| 框架 | React 18 + Vite + TypeScript | 生态成熟、构建快 |
| 路由 | react-router v6 | 三个页面，需要路由与守卫 |

## 12. 非功能需求

- **响应性**：所有 LLM 端点同步阻塞，前端必须有明确的 loading 态，禁止静默等待。
- **可访问性**：keyboard 可操作导演面板；颜色对比满足 WCAG AA；内心独白不只靠颜色区分（加图标/文字标签）。
- **中文优先**：全部文案中文。
- **无 secret**：前端永不接触 LLM API key。
- **视觉基调**："创世神工作台"——深色舞台感、正文与数据区视觉分层、异变/独白用强调色。

## 13. MVP 范围与里程碑

**M1（本次交付，必须完成）**
- 世界广场（列表 + 新建 + 进入）
- 世界演播室（回合推进、创世神视图、导演事件注入、事件流抽屉、角色侧栏）
- 小说工作台（生成大纲、撰写全部/指定、章节阅读、导出 Markdown）

**M2（增强，可选）**
- 自动连播 + 暂停
- 回合卡片可折叠/深度展开（查看某角色某回合全部记忆）
- 小说侧可"以某角色视角重写一章"（需后端支持）
- 世界可视化地图（后续）

## 14. 验收标准

1. 从广场创建一个《荒山茶馆》世界并进入演播室，能连续推进 3 回合，每回合展示场景正文 + 全角色创世神视图。
2. 注入定向导演事件后，新回合顶部出现【世界异变】横幅，目标角色独白体现感知。
3. 事件流抽屉能按回合查看内心/说/行动/叙述/异变五类事件。
4. 小说工作台能生成大纲、撰写全部章节（有进度）、逐章阅读、导出合法 Markdown。
5. 所有 LLM 端点均有 loading 态；后端不可达有明确错误提示。
6. 刷新页面后世界进度不丢（后端持久化，前端仅按 world_id 重新拉取）。

## 15. 已知后端限制（前端需适配或与后端协同解决）

1. **无预设列表端点**：目前只有 `presets/tavern.yaml`。M1 前端可硬编码该预设；建议后端后续提供 `GET /api/presets`。
2. **step 同步阻塞**：多角色并行 LLM 尚在后端做；前端以 loading 承接。后续后端可升级为 SSE/任务队列，前端留好替换接口。
3. **无鉴权**：单机工具型，默认局域网可用；若公开部署需加鉴权（后续）。
4. **世界 id 即持久化键**：前端需校验 world_id 合法字符（后端以字符串直接入库）。
